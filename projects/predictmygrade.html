PredictMyGrade

A Django academic analytics application designed to show end-to-end product engineering: persisted student data, forecasting-style tools, study planning, feature gating, polished UX and browser-level verification.

Representative portfolio interface preview

The challenge

Academic tools often stop at simple grade calculators. I wanted to explore a broader product: one place where a student could record performance, understand progress, test possible outcomes and organise study activity without the interface feeling like a collection of unrelated features.

The core engineering challenge was product cohesion: keeping data, navigation, calculations, premium-style journeys and fallback behaviour consistent across a growing Django application.

What I built

  • Persistent university and GCSE-style academic workflows with weighted progress summaries.
  • Dashboards, targets, what-if forecasting, goals, deadlines, snapshots and study-planning flows.
  • Authentication and demo-safe account journeys.
  • AI-assisted report and mentor-style experiences with fallback behaviour rather than hard dependency on an external service.
  • Demo-oriented premium feature gating and subscription-management journeys.
  • Admin views for operational visibility, user management and system health.
  • Backend tests and Playwright browser smoke tests covering key user journeys.

Engineering decisions

  • Portfolio-first positioning: features are presented as demonstrable product engineering rather than pretending the service is a production education platform.
  • Progressive complexity: core academic data remains understandable even as forecasting, planning and premium-style features are layered on top.
  • Verification: browser-level smoke tests complement backend tests so critical journeys can be checked from the user’s point of view.
  • Graceful fallback: optional AI-style flows are designed not to break the wider experience when integrations are unavailable.

Architecture

Browser ↓ Django templates + views ↓ Models / forms / services / tasks ↓ SQLite locally → PostgreSQL-ready structure ↓ Optional integrations ↓ Backend tests + Playwright E2E smoke tests

What this demonstrates

This is my strongest full-stack portfolio project because it shows more than framework knowledge. It demonstrates how I structure a multi-feature product, improve consistency across screens, think about failure states, test user journeys and keep the application understandable as scope grows.
