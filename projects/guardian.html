Guardian Antivirus

A Linux desktop security application built around Python, Qt and ClamAV, combining malware scanning, real-time filesystem monitoring, quarantine workflows and persistent protection state in one user-facing interface.

Representative Guardian Antivirus interface preview

The challenge

ClamAV provides mature scanning capabilities, but using security tooling directly can feel fragmented for a desktop user. Guardian explores how those lower-level capabilities can be orchestrated behind a clearer application layer with visible protection state, history and safe file handling.

The interesting engineering work is the coordination between UI state, background monitoring, scanning, quarantine and persistent application data.

What I built

  • Quick, full and custom scan workflows exposed through a PySide6 desktop interface.
  • ClamAV-backed file scanning and result handling.
  • Real-time filesystem monitoring using a watcher process.
  • Quarantine management for detected files.
  • SQLite-backed scan history and application state.
  • Protection-status cards, tray integration and settings controls.
  • Logging and modular scanner, notifier, database and quarantine components.

Engineering decisions

  • Separation of concerns: scanning, monitoring, persistence, quarantine and notifications are kept as distinct components rather than being embedded directly in the UI.
  • Defensive UX: security state needs to be clear without implying protection that is not actually active.
  • OS-aware behaviour: the project has to account for Linux permissions, service availability and long-running background processes.
  • Persistent evidence: scan records and protection state make the application easier to inspect and troubleshoot.

Architecture

PySide6 / Qt UI ↓ Protection state + Scan Manager ↙ ↓ ↘ ClamAV Watcher Quarantine ↘ ↓ ↙ SQLite ↓ Logs / Notifier

What this demonstrates

Guardian is a strong portfolio piece because it moves beyond conventional CRUD development. It demonstrates operating-system integration, process orchestration, defensive programming, desktop UI design and the need to verify that application state matches what the underlying security services are actually doing.
